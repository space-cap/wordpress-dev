# 개발자 노트 (Developer's Note) — 개발계획서

> **작성일**: 2026년 7월 18일  
> **작성자**: 이영현 (프로그래머 채용 지원 포트폴리오)  
> **프로젝트**: 법무법인 파라딘 커스텀 워드프레스 테마 (`paradin-theme`) 리뉴얼 모의 프로젝트

---

## 1. 📋 개요

이 문서는 `paradin-theme` 사이트에 **채용 담당자를 위한 개발자 정보 안내 기능**을 추가하기 위한 개발 계획서입니다.

법무법인 파라딘의 프로그래머 채용에 지원하면서, 본 사이트가 **단순한 클론 프로젝트가 아니라 실력을 검증할 수 있는 포트폴리오**임을 방문자(채용 담당자)에게 명확히 전달하는 것이 목적입니다.

---

## 2. 🎯 구현 목표

### 2-1. 상단 고정 안내 배너 (Announcement Banner)

사이트 최상단(GNB 위)에 **항상 고정된 안내 바**를 추가합니다.

- **문구**:
  ```
  본 사이트는 법무법인 이엘의 프로그래머 채용 지원을 위해 커스텀 워드프레스 테마로 직접 제작한 모의 리뉴얼 프로젝트입니다. [개발자 노트 보기]
  ```
- **`[개발자 노트 보기]`** 클릭 시 → `/developer-note/` 페이지로 이동
- 배너는 스크롤과 무관하게 항상 화면 최상단에 고정 (`position: fixed`)
- GNB(기존 nav 메뉴)가 배너 아래에 위치하도록 레이아웃 조정

### 2-2. 개발자 노트 페이지 신설 (`/developer-note/`)

GNB 메뉴에 **"개발자 노트"** 항목을 추가하고, 전용 페이지 템플릿 파일을 제작합니다.
페이지는 세 개의 섹션으로 구성됩니다:

| 섹션 | 내용 |
|---|---|
| **① 기존 사이트 문제점 분석** | `paradin.com` 원본 사이트를 분석하여 발견한 UX·성능·SEO 개선점 |
| **② 커스텀 테마 개발 목적** | 왜 플러그인 빌더가 아닌 커스텀 테마를 선택했는지 기술적 의사결정 근거 |
| **③ 기술 스택 및 성과 어필** | 사용 기술 목록, 구현 난이도, 측정 가능한 개선 지표 |

## 3. 🔍 기존 사이트(`paradin.com`) 문제점 분석

> 이 분석은 크롬 DevTools, Lighthouse, PageSpeed Insights를 활용하여 직접 진행한 역공학(Reverse Engineering) 결과입니다.

### 3-1. 성능(Performance) 문제

| 문제 항목 | 내용 | 개선 방향 |
|---|---|---|
| **이미지 포맷 미최적화** | 일부 이미지가 JPG/PNG 형식으로 제공됨 (차세대 포맷 미사용) | PHP GD 라이브러리로 업로드 시 WebP 자동 변환 (`paradin_convert_upload_to_webp`) |
| **렌더 블로킹 리소스** | 외부 폰트·스크립트가 FCP(First Contentful Paint)를 지연시킬 가능성 | `wp_enqueue_*` 훅으로 CSS/JS 로드 순서 최적화, 스크립트는 `footer:true` 설정 |
| **영상 배경 무거운 초기 로드** | Hero 섹션의 배경 영상이 페이지 진입 즉시 스트리밍 시작 | iframe `loading="lazy"` 및 파사드(Facade) 패턴 적용 가능 |

### 3-2. SEO 문제

| 문제 항목 | 내용 | 개선 방향 |
|---|---|---|
| **메타 디스크립션 부재** | 페이지별 고유 description 태그 없음 | `functions.php`에서 페이지 slug별 description 자동 주입 |
| **OG(Open Graph) 태그 부재** | SNS 공유 시 사이트 정보가 노출되지 않음 | `og:title`, `og:description`, `og:image` 태그 추가 |
| **시맨틱 구조 개선 여지** | 일부 영역에서 `<div>` 남용, 헤딩 계층 검토 필요 | `<section>`, `<article>`, `<h1>`~`<h3>` 계층 정비 |

### 3-3. 접근성(Accessibility) 문제

| 문제 항목 | 내용 | 개선 방향 |
|---|---|---|
| **키보드 내비게이션** | 드롭다운 메뉴가 마우스 hover에만 반응 | JS `focus` 이벤트 추가로 키보드 접근성 보완 |
| **동영상 배경 대체 텍스트** | 백그라운드 영상에 `aria-hidden="true"` 미적용 | 스크린리더 사용자 경험 개선을 위해 `aria-hidden` 처리 |
| **색상 대비** | GNB 투명 상태에서 일부 텍스트의 명도 대비 비율 검토 필요 | WCAG 2.1 AA 기준(4.5:1) 준수 여부 확인 및 조정 |

### 3-4. 유지보수성 문제

| 문제 항목 | 내용 | 개선 방향 |
|---|---|---|
| **환경 재현 불가** | 원본 사이트 배포 환경 공유 불가 | `docker-compose.yml`로 1분 내 동일 환경 재현 |
| **콘텐츠 수정 난이도** | HTML 직접 편집 필요 추정 | WordPress CMS로 비개발자도 게시물 관리 가능 |
| **테마 버전 관리 부재** | 코드 이력 추적 어려움 | Git 버전 관리로 모든 변경 이력 추적 |

## 4. 🧠 커스텀 테마 개발 목적

### 4-1. 왜 Elementor 같은 플러그인 빌더를 쓰지 않았는가?

이 프로젝트의 핵심 목적은 **"코드로 실력을 증명"**하는 것입니다.
드래그&드롭 도구로는 PHP, JavaScript, CSS 실력을 보여줄 수 없습니다.

| 비교 항목 | Elementor 빌더 | `paradin-theme` 커스텀 테마 |
|---|---|---|
| **개발 자유도** | 플러그인 제약 내에서만 가능 | PHP 템플릿 100% 완전 제어 |
| **성능** | 불필요한 CSS/JS 수백 KB 자동 포함 | 필요한 라이브러리만 선택적 로드 |
| **SEO 제어** | 구조화 데이터(JSON-LD) 주입 어려움 | `wp_head()` 훅으로 완전 제어 |
| **채용 어필** | "플러그인 사용 능력" 증명 | "PHP·JS·CSS 실력" 직접 증명 |
| **기술 복잡도** | 드래그&드롭, 코딩 불필요 | 템플릿 계층, WordPress Hook, 바닐라 JS 인터랙션 구현 |

### 4-2. WordPress 선택 이유

법무법인의 업무 특성상 다음과 같은 요소가 중요합니다:

- **뉴스·칼럼의 지속적 업데이트**: WordPress CMS로 비개발자도 쉽게 관리
- **채용 공고 게시**: `page-careers.php` 템플릿으로 구조화된 채용 페이지 운영
- **확장성**: 플러그인 생태계 활용으로 미래 기능 추가 용이
- **시장 점유율**: 전 세계 CMS 중 점유율 1위(43%)로 가장 범용적인 기술

### 4-3. Docker 기반 개발 환경 선택 이유

```
문제: "내 PC에서는 됩니다" 현상 — PHP·MySQL 버전 차이로 인한 환경 불일치
해결: docker-compose.yml 하나로 개발 환경 코드화
결과: docker compose up -d 한 줄로 동일 환경 즉시 재현 (약 60초)
```

Mac Mini, Windows WSL, Linux 서버 어디서나 동일하게 동작하는 이식성을 확보했습니다.

## 5. 🛠️ 기술 스택 및 성과

### 5-1. 기술 스택 (Tech Stack)

#### 프론트엔드

| 기술 | 역할 | 선택 이유 |
|---|---|---|
| **PHP 8.x** | WordPress 템플릿 엔진 | WordPress 핵심 언어 |
| **Tailwind CSS (CDN)** | 유틸리티-퍼스트 스타일링 | 빠른 반응형 UI 구현, 클래스명으로 의도 명확화 |
| **Vanilla JavaScript** | 탭 인터랙션, GNB 스크롤 효과, 다크모드 | 프레임워크 의존 없이 순수 JS로 복잡한 UI 구현 |
| **AOS.js 2.3.1** | 스크롤 트리거 애니메이션 | 자연스러운 콘텐츠 등장 효과 |
| **Swiper.js** | 이미지 슬라이더/캐러셀 | 모바일 친화적 터치 슬라이드 |

#### 백엔드 및 인프라

| 기술 | 역할 | 선택 이유 |
|---|---|---|
| **WordPress 6.x** | CMS 플랫폼 | 콘텐츠 관리 + 커스텀 테마 개발 |
| **Docker + docker-compose** | 로컬 개발 환경 컨테이너화 | 환경 재현성 100% 보장 |
| **MySQL 8.0** | 데이터베이스 | WordPress 공식 지원 DB |
| **Nginx + PHP-FPM** | 웹서버 + PHP 실행 환경 | 프로덕션 환경 동일 구성 |

#### 폰트 & 디자인 시스템

| 요소 | 적용 |
|---|---|
| **Pretendard** | 한글 본문 폰트 (가독성 최우선) |
| **Lora** | 영문 헤딩 폰트 (프리미엄 세리프체) |
| **컬러 팔레트** | `#1a1a1a` (다크), `#006eff` (PARADIN 블루), `#6d6d6d` (그레이) |
| **반응형 브레이크포인트** | 모바일 `< 1024px` / 데스크톱 `>= 1024px` |

### 5-2. 구현 난이도 하이라이트

#### ① Glassmorphism GNB (상단 메뉴)
- 스크롤 전: 완전 투명 (`bg-transparent`)
- 스크롤 후: 배경 블러 + 반투명 (`backdrop-blur`, `bg-white/80`)
- Vanilla JS로 `scrollY` 값 감지, CSS 클래스 동적 토글

#### ② 인터랙티브 탭 컴포넌트
- Communication / Focus / Reasonable 탭 전환 시
- 텍스트 콘텐츠 + 오른쪽 이미지 + 프로그레스 바 너비 3가지 동시 연동
- `requestAnimationFrame`을 활용한 부드러운 바 애니메이션

#### ③ 다크모드 지원
- `localStorage`에 사용자 선호 저장
- 시스템 설정(`prefers-color-scheme`) 감지 후 자동 적용
- 깜빡임(Flash of Unstyled Content) 방지를 위한 인라인 IIFE 스크립트

#### ④ WebP 자동 변환
- 이미지 업로드 시 PHP GD 라이브러리로 JPEG/PNG → WebP 자동 변환
- 원본 파일 삭제로 디스크 용량 절약
- 압축 품질 82%로 화질/용량 최적 균형점 적용

### 5-3. 개선 지표 (Quantified Results)

| 지표 | 원본 방식 (Elementor 가정) | `paradin-theme` 커스텀 |
|---|---|---|
| **초기 JS 번들 크기** | ~500KB 이상 (플러그인 포함) | AOS + Swiper 약 60KB |
| **불필요 CSS** | 수백 개의 미사용 클래스 | Tailwind CDN (필요한 것만 JIT 생성) |
| **이미지 포맷** | JPG/PNG 원본 | WebP 자동 변환 (평균 30~50% 용량 절감) |
| **환경 재현 시간** | 서버 셋업 수십 분 | `docker compose up -d` 약 60초 |
| **페이지 템플릿 수** | 단일 빌더 템플릿 | PHP 템플릿 8개 (페이지별 독립 제어) |

## 6. 📁 구현 계획 (Implementation Plan)

### 6-1. 변경 파일 목록

| 파일 | 작업 유형 | 내용 |
|---|---|---|
| `header.php` | **수정** | 최상단 고정 배너 HTML 추가, GNB top 위치 조정 |
| `functions.php` | **수정** | `developer-note` 페이지 자동 생성 로직 추가 |
| `page-developer-note.php` | **신규** | 개발자 노트 전용 페이지 템플릿 생성 |
| `style.css` | **수정** | 배너 CSS 스타일 추가 (배너 높이 CSS 변수화) |

### 6-2. 구현 순서

```
Step 1. header.php — 배너 HTML 삽입 (body 바로 아래, GNB 위)
   - CSS 변수 선언: --banner-height: 48px
   - GNB nav의 top 값을 배너 높이만큼 내림: top: var(--banner-height)
   - 배너 z-index는 GNB(z-50)보다 높은 z-[60] 이상으로 설정

Step 2. style.css — 배너 고정 스타일 정의
   - position: fixed; top: 0; z-index: 100
   - body에 padding-top 추가 (배너에 가려지는 콘텐츠 방지)

Step 3. functions.php — developer-note 페이지 자동 생성 추가
   - paradin_create_default_pages() 함수 내 배열에 항목 추가
   - slug: 'developer-note', title: '개발자 노트', template: 'page-developer-note.php'

Step 4. page-developer-note.php — 개발자 노트 페이지 템플릿 제작
   - 섹션 1: 기존 사이트 문제점 분석 (비교 테이블, 시각 강조)
   - 섹션 2: 커스텀 테마 개발 목적 (의사결정 근거, 코드 예시)
   - 섹션 3: 기술 스택 및 성과 어필 (태그 칩, 지표 카드)

Step 5. header.php — GNB에 '개발자 노트' 메뉴 링크 추가
   - 데스크톱 메뉴 ul에 li 항목 추가
   - 모바일 드롭다운 메뉴에도 동일하게 추가
```

### 6-3. 배너 디자인 명세

```
배경색: #1a1a1a (paradin-dark) 또는 PARADIN 블루 계열 어두운 색상
텍스트: 흰색 (#ffffff), 폰트 크기: 14px (모바일) / 15px (데스크톱)
높이: 48px (고정)
[개발자 노트 보기] 버튼: 밑줄 + 볼드, hover 시 색상 변화
닫기(X) 버튼: 우측에 추가하여 UX 개선 (localStorage로 숨김 상태 저장)
```

## 7. ✅ 검증 계획

### 수동 검증 체크리스트

- [ ] `http://localhost:8088/` 접속 시 상단에 안내 배너가 표시되는가
- [ ] 배너가 스크롤해도 항상 화면 최상단에 고정되는가
- [ ] `[개발자 노트 보기]` 클릭 시 `/developer-note/` 페이지로 이동하는가
- [ ] GNB 메뉴에 `개발자 노트` 항목이 표시되는가
- [ ] `page-developer-note.php` 템플릿이 정상 렌더링되는가
- [ ] 기존 GNB 스크롤 효과(Glassmorphism)가 배너 추가 후에도 정상 동작하는가
